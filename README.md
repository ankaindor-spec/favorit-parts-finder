# Favorit Parts Finder

Поиск автозапчастей по артикулу в сервисе «Проценка» Favorit. Приложение показывает производителей найденной детали, а после выбора производителя — складские предложения самой детали и её аналогов: наименование, бренд, цену и остаток по каждому складу отдельно.

Сайт: https://ankaindor-spec.github.io/favorit-parts-finder/

Репозиторий: https://github.com/ankaindor-spec/favorit-parts-finder

## Возможности

- Поиск производителей по номеру детали.
- Повторный запрос предложений после выбора производителя, вместе с аналогами.
- Отдельная строка или карточка на каждое складское предложение. Остатки разных складов не складываются.
- Состояния ожидания, пустого ответа, ошибки сервиса и отсутствующего ключа.
- Адаптивный экран: таблица от 1024px, карточки на более узких экранах.

## Стек

React, Vite, Redux Toolkit (`createAsyncThunk`), React Hooks, SCSS, Fetch API, lucide-react, Vitest, React Testing Library, ESLint. Сборка публикуется на GitHub Pages через GitHub Actions. Отдельного backend нет: браузер обращается к API напрямую.

## Архитектура

Статическое приложение. React вызывает Fetch, Vite собирает `dist`, GitHub Pages отдаёт эту папку.

Два асинхронных сценария:

1. Поиск производителей по артикулу: `GET` без `brand`.
2. Предложения выбранной позиции: `GET` с `number`, `brand`, `analogues=on` и `info=on`.

Запросы живут в `shared/api`. Разбор ответа — в нормализаторах `entities`, не в компонентах. Состояние запросов — в Redux. Команды `features/search-session` сбрасывают прошлые данные, не пускают повтор одинакового запроса, пока он выполняется, и прерывают предыдущий запрос. В редюсерах ответ принимается только если его `requestId` ещё актуален, поэтому опоздавший ответ не затирает новый.

У каждого этапа статусы `idle`, `loading`, `succeeded`, `failed`. Новый поиск очищает производителей и предложения. Смена производителя очищает предложения. Пустой ввод не уходит в API.

Цена и остаток берутся из `warehouses[].price` и `warehouses[].stock`. Поля `goods.price` и `goods.count` на экран не выводятся: документация прямо запрещает использовать цену товара, а остаток показывается по каждому складу. Валюты в ответе нет, поэтому рядом с числом нет знака валюты.

## Структура каталогов

```text
src/
  app/                провайдер store, стили, корень интерфейса
  pages/parts-search  сборка экрана поиска
  widgets/            панель поиска, список брендов, список предложений
  features/           thunk-и поиска и выбора бренда, команды сценария
  entities/           нормализация детали, бренда и предложения
  shared/api          HTTP-клиент и методы сервиса проценки
  shared/lib          формат цены, количества и даты отгрузки
  shared/ui           сообщения состояний
tests/                API, Redux и интерфейс; сеть замокана
```

## Переменные окружения

Скопируйте `.env.example` в `.env`.

Ключ — публичное демонстрационное значение из официального PDF «Описание работы Web-Сервиса: Проценка» от 06.03.2023: https://lk.favorit-parts.ru/static/wsprice.pdf. В примерах запросов указан `00000000-0000-0000-0000-000000000001`. Это не личный секрет.

`VITE_FAVORIT_API_KEY` читается как `import.meta.env.VITE_FAVORIT_API_KEY`. Все переменные `VITE_` вшиваются в клиентский бандл на этапе сборки. Смена `.env` после `npm run build` сам бандл не обновляет: нужна новая сборка. Файл `.env` не коммитится.

Публичный демо-ключ уже записан в `.env.development` и `.env.production`. Поэтому `npm run dev` и `npm run build` работают без ручного копирования `.env`. В unit-тестах используется отдельный `.env.test` с фиктивным ключом, запросы к сервису не выполняются.

## GitHub Pages и Actions

Workflow: `.github/workflows/deploy.yml`.

- Push в `main` и любой pull request: установка, `npm test`, `npm run lint`, `npm run build`.
- Деплой `dist` только при push в `main`.
- Шаги деплоя: `actions/checkout`, `actions/setup-node` (Node LTS), `actions/configure-pages`, `actions/upload-pages-artifact`, `actions/deploy-pages`.
- Пакет `gh-pages` не используется.
- Если в репозитории задана переменная или секрет `VITE_FAVORIT_API_KEY`, сборка берёт её. Пустое значение переменную не подставляет и не затирает ключ из `.env.production`.

Источник Pages уже выбран: GitHub Actions. Сайт опубликован по адресу https://ankaindor-spec.github.io/favorit-parts-finder/

## Интеграция с API

Документ: https://lk.favorit-parts.ru/static/wsprice.pdf (описание от 06.03.2023).

Контракт, на котором собран клиент:

| | |
| --- | --- |
| Базовый URL в документации | `http://api.favorit-parts.ru/hs/hsprice/` |
| URL в приложении | `https://api.favorit-parts.ru/hs/hsprice/` |
| Метод | `GET` |
| Ключ | query-параметр `key` |
| Запрос 1 | `key`, `number` |
| Запрос 2 | `key`, `number`, `brand`, `analogues=on`, `info=on` |
| Успех | JSON-объект с массивом `goods` |
| Ошибка | JSON с полем `error` |
| Не найдено | `goods` из одной пустой записи с нулевым `goodsID` |

Позиция: `goodsID`, `brand`, `number`, `name`, `rate`, `warehouses`, при втором запросе ещё `analogues` и `notRefund`. Цена `goods.price` в документации помечена как устаревшая и не показывается.

Склад: `id`, `code`, `own`, `shipmentDate`, `price`, `stock`, `notRefund`. На экране используются код склада, признак своего склада, дата отгрузки, цена и остаток. Несколько складов с одним кодом и разной ценой остаются разными строками.

Поля `brand_quality`, `defect`, `sale` и `warehouseShipping` в живом ответе встречаются, но в таблице параметров PDF не описаны. Приложение их не показывает и не придумывает для них смысл.

Дата отгрузки выводится так, как пришла в строке API (календарный день и часы до смещения зоны). Время не пересчитывается в Europe/Samara, чтобы не сдвигать час, до которого можно заказать отгрузку.

Спецсимволы в номере и бренде кодирует `URLSearchParams` (`&` становится `%26`, как требует PDF).

Тексты ошибок на русском. Сырой текст `error`, имена полей и трассировки на экран не выводятся. Известные коды: `Empty key!`, `Invalid key client!`, наблюдаемый вживую `Invalid access key`, `Empty number goods!`, `Request quota exceeded!`.

### Проверка CORS

Из этого окружения проверены и curl, и настоящий браузер (headless Chrome):

- `https://api.favorit-parts.ru/hs/hsprice/` отвечает `200` и JSON, заголовок `Access-Control-Allow-Origin: *`. Запрос из страницы на HTTP и из страницы на HTTPS проходит.
- `http://api.favorit-parts.ru/hs/hsprice/` из curl и со страницы `http://` тоже отвечает, но из страницы `https://` браузер блокирует его как mixed content (`TypeError: Failed to fetch`).
- Поэтому клиент использует HTTPS. Отдельный прокси не добавлялся.

Пример из PDF для ручной проверки: артикул `01089`, затем любой вернувшийся производитель, например OSSCA.

## Известные ограничения

- Второй запрос с аналогами бывает большим. Для артикула `01089` и бренда FEBI ответ содержит сотни складских строк; для `7160500039S` и MEYLE — ещё больше. Список открывается порциями по 40 строк.
- Демонстрационный ключ общий, у сервиса есть лимит запросов.
- Ключ виден в собранном JavaScript. Для опубликованного демо-ключа это ожидаемо; прятать его backend-ом нельзя в рамках этой архитектуры.
- Валюта, срок доставки в днях и характеристики, которых нет в ответе, не выдумываются.
- Вложенные аналоги читаются на два уровня. В проверенных ответах аналоги лежат сразу внутри найденной позиции.

## Ключ на GitHub Pages

Сообщение «Не задан ключ доступа» появляется, только если в собранный JavaScript попала пустая строка. Переменная `VITE_*` читается во время `npm run build`, а не при открытии сайта.

Первая публикация собралась без ключа: в репозитории не было переменной Actions `VITE_FAVORIT_API_KEY`. В списке Environments при этом есть среды с именами `Variables` и `VITE_FAVORIT_API_KEY`. Среда развёртывания — это не переменная, workflow её не читает. Эти две среды можно удалить, на сборку они не влияют.

Сейчас публичный демо-ключ лежит в `.env.production`, и сборка Pages использует его сама. Отдельная переменная больше не обязательна. Если её всё же нужно заменить, это делается так: Settings → Secrets and variables → Actions → вкладка **Variables** → New repository variable. Имя: `VITE_FAVORIT_API_KEY`. Не создавайте для этого новую Environment. После изменения переменной нужен новый запуск workflow «CI and Pages»: уже опубликованный бандл сам не обновится.
